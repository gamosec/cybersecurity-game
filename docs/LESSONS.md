# الدروس المستفادة والأخطاء التي وقعنا فيها

كل بند هنا حدث فعلًا أثناء بناء المشروع. اقرأه قبل تعديل الرسم أو CSS أو المحرك.

## الرسم و SVG

| المشكلة | السبب | الحل / القاعدة |
|---|---|---|
| نص عربي داخل الرسم ينزاح خارج صندوقه | في صفحة RTL يعني `text-anchor="end"` الحافة **اليسرى** | استخدم `middle`، أو `start` مع `direction="rtl"`. الفاحص يحذّر من `end` |
| تدرجات/مرشحات تتعطل أو تظهر بألوان خاطئة | معرّفات `id` مكررة؛ القائمة ترسم **كل** المشاهد المصغّرة معًا | بادئة فريدة لكل سيناريو (`s3-`, `m1-`, مقدمة `s3i-`). `show()` يفرّغ رسومات الشاشات غير النشطة. الفاحص يفحص التكرار |
| مصغّر السيناريو يظهر مشوّهًا | قاعدة CSS `.card-thumb svg {…}` أصابت SVG المتداخل داخل المشهد | استهدف الحاويات بـ `> svg` (وهكذا في intro/results) |
| منطقة نقر عنصر تغطي عناصر أخرى فلا يمكن الضغط عليها | `data-hotspot` يحسب `getBBox()` للمجموعة كلها، فالفقاعات والأشعة تضخّمه | أخرج الزخرفة من المجموعة أو استخدم `data-hit="self"` مع `class="hit"` |
| عنصر قابل للنقر مختبئ خلف الشريط العلوي | الـ HUD يغطي أول ~132px | لا تضع عناصر نقر في أعلى المشهد (كاميرا المراقبة نُقلت لهذا السبب) |
| نبتة أو أثاث يخفي شاشة محطة | لا ترتيب عمق تلقائي (خوارزمية الرسّام) | رتّب الرسم من الخلف للأمام؛ انظر الصورة بعد كل تعديل وانقل العناصر المزعجة |
| كرسي يخفي الجالس عليه | ارتفاع ظهر الكرسي أكبر من الشخص | اخفض الظهر (46) وارفع الشخص (z=56..122) |
| ظل/ضوء (poly شفاف) يمنع النقر | عنصر فوق المحطة يلتقط الأحداث | `pointer-events="none"` على الزخارف، أو ارسمها قبل المحطة |

## واجهة وتفاعل

- **وميض عند حافة البطاقة / "element is not stable"** في الاختبار: كان بسبب `:hover { transform: translateY(-2px) }` يحرّك العنصر تحت المؤشر. **لا transform عند hover**؛ استخدم `border-color`/`box-shadow`.
- **الأرقام تنعكس في RTL** ("3 / 1" بدل "1 / 3"): ضع `dir="ltr"` على العنصر الذي يحوي الرقم والشرطة.
- **الهاتف لا يحدّث الصفحة بعد النشر**: GitHub Pages يرسل `cache-control: max-age=600` والهواتف تحتفظ بالقديم أكثر. الحل: `?v=N` في **كل** وسوم index.html وارفعه مع كل نشر (الفاحص يفرض التطابق).
- **نافذة التلميح فوق نافذة الأسئلة** (الهاتف): أخفِ الـ toast عند فتح تحدٍ.
- **الخيارات الخاطئة الغامضة** تولّد شكاوى: راجع قواعد المحتوى (فقرة "الخطأ لا يقبل الجدل").
- **المؤقت**: يتوقف أثناء قراءة المقدمة والتغذية الراجعة ونافذة المساعدة فقط. يستمر أثناء البحث والإجابة (يشبه مرجع المستخدم).
- **زر التأكيد**: لا يُقبل بلا اختيار (اهتزاز + toast). في المهام زر "إرسال" معطّل حتى يوجد اختيار.
- الصوت لا يعمل قبل أول تفاعل (سياسة المتصفحات)؛ هذا متوقع.
- **غير متسق (قرار مفتوح)**: مكافأة الوقت في سيناريوهات الغرفة تُمنح دائمًا، وفي المهام عند النجاح فقط. انظر `STATUS.md`.

## الاختبار

- اختبار يعتمد على `evaluate` يتجاوز اختبار النقر الحقيقي. استخدم `locator.click()` (Playwright يتحقق أن العنصر قابل للنقر وغير مغطّى). هكذا اكتُشف تداخل رسالة SMS مع الشاشة.
- بعد تغيير المنطق، **اختبر أن الاختبار يفشل** (تخريب متعمد في نسخة مؤقتة) — فعلنا ذلك للفاحص ولـ e2e. فاحص بلا اختبار فشل لا يُعتمد عليه.
- اختبار السيناريو المولَّد من القالب كشف أن `icon:` الصريح كان يُتجاهل في الغرفة (أُصلح بـ `Icons.forOption` وأُضيف تحقق وجود الصور في e2e).
- تحجيم الهاتف: `devices['Pixel 7']` في Playwright. تذكّر `scrollIntoViewIfNeeded` لأن المشهد قابل للسحب أفقيًا.
- الصور لا تُغني عن النظر: افتحها. أخطاء مثل نص مقصوص وعناصر متراكبة لا تكشفها الاختبارات.

## الأيقونات

- ترتيب `rules` مهم: القاعدة الأعمّ (`/التنصّت/`) يجب أن تأتي بعد الأخص (`/كاميرا التلفاز/`). عند إضافة قاعدة اختبر نصوصًا قائمة بلوحة بصرية (اطبع كل النصوص مع أيقوناتها في HTML وصوّرها).
- شارة `hook` الأولى بدت كنوتة موسيقية: أعيد رسمها على خلفية حمراء مع صنارة بيضاء.
- لا تضع `id` داخل رسم أيقونة (تتكرر عشرات المرات في الصفحة).

## الأمان والمحتوى

- المهام الهجومية: **مستوى التوعية فقط** (فئات عامة، تنتهي بدرس دفاعي). عند أي شك قلّل التفاصيل. لا خطوات ولا أدوات ولا تفاصيل تجاوز.
- محتوى الأسئلة كتبه Claude ولم يراجعه مختص أمن معلومات؛ **اطلب مراجعة بشرية قبل الاعتماد الرسمي**.
- الإجابات في شيفرة المتصفح بالضرورة. للاختبارات المُقيَّمة يلزم خادم.

## سير العمل

- الفرع المخصّص للتطوير في الجلسات السحابية: `claude/cybersecurity-escape-room-scenario-1-0my2fq`؛ و`main` أُنشئ منه بطلب المستخدم لأجل Pages، ويُحدَّث بدفع `HEAD:main` (fast-forward). لا PR (لم يُطلب).
- لا `gh` CLI؛ لأي عمل على GitHub استخدم أدوات `mcp__github__*`.
- ملفات الاختبار المؤقتة كانت تضيع بنهاية الجلسة؛ لذلك صارت في `tests/` و`tools/` داخل المستودع.

## الرحلات (journey)

- **منطقة النقر `rect.hit` يجب أن تكون آخر ابن** في المجموعة (`appendChild`)، وإلا غطّاها الرسم فيرفض Playwright النقر ("intercepts pointer events").
- **عناصر متحركة بـ CSS داخل المجموعة القابلة للنقر** تجعل Playwright يرى العنصر "غير مستقر". ضعها في مجموعة منفصلة `pointer-events="none"`.
- في اختبارات الرحلة: انتظر انتهاء الستارة والكاميرا (~2.3s) قبل النقر، ولا تنقر عناصر خلف عناصر أخرى (مثل فنجان خلف حامل QR).
- **HUD يغطي أعلى ~132px** من العالم؛ احسب `cam` بحيث لا يتخبأ شيء هناك.
- نص SVG داخل العالم: `text-anchor="end"` يضع الحافة اليسرى (مشكلة RTL). استخدم `start` مع `direction="rtl"` أو `direction="ltr"` حسب الجهة.
